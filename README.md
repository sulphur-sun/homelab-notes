# homelab-notes — Go + Rust

Учебный проект: сервис заметок с REST API на Go и отдельным сервисом хранения на Rust.
Демонстрирует взаимодействие двух языков через HTTP/JSON, разделение ответственности
между сервисами и обработку ошибок на границе процессов.

## Зачем этот проект

Цель — не просто «сделать CRUD», а разобраться, как устроены распределённые
системы на практике: как два сервиса на разных языках договариваются о контракте,
как обрабатывать ошибки upstream, как разделять API и хранение так, чтобы одно
можно было заменить, не переписывая другое.

## Архитектура

```
┌──────────┐   HTTP    ┌─────────────┐   HTTP/JSON   ┌───────────────┐
│ Браузер  │ ────────► │  Go API     │ ────────────► │  Rust storage │
│ (HTML)   │ ◄──────── │  :8090      │ ◄──────────── │  :8091        │
└──────────┘           └─────────────┘               └───────────────┘
                                                       │
                                                       ▼
                                                  files/*.json
```

**Go-сервис** — публичный API: принимает запросы от браузера, рендерит HTML,
выступает клиентом к Rust-сервису. Отвечает за пользовательский интерфейс и
обработку ошибок upstream.

**Rust-сервис** — внутренний сервис хранения: принимает JSON, сохраняет заметки
в отдельные файлы, возвращает список. Не имеет публичного доступа.

## Стек и почему именно он

| Компонент       | Технология                        | Почему                                                                |
|-----------------|-----------------------------------|-----------------------------------------------------------------------|
| Публичный API   | Go + `net/http` + `html/template` | Простой деплой, отличная стандартная библиотека, минимум зависимостей |
| Сервис хранения | Rust + `axum` + `tokio` + `serde` | Async I/O, строгая типизация, безопасная работа с файлами             |
| Формат обмена   | JSON                              | Явный контракт, читаемость, лёгкая отладка через `curl`/Postman       |
| Хранение        | Файлы `<uuid>.json`               | Простое, прозрачное, легко инспектировать руками                      |                     

## Возможности

- Создание заметки через HTML-форму (Post/Redirect/Get).
- Просмотр списка заметок.
- Валидация и логирование входящих запросов.
- Обработка ошибок upstream: при недоступности Rust-сервиса пользователь
  получает `502 Bad Gateway` с внятным сообщением, а не пустую страницу.
- Таймауты HTTP-клиента (5 секунд), переиспользование соединений.
- Конфигурация пути хранения через переменную окружения `DB_DIR`.
- Запуск обоих сервисов одной командой (`.bat`-скрипт для Windows).

## Запуск

### Требования

- Go 1.22+
- Rust (stable, edition 2021+)
- Windows / Linux / macOS

### Через `.bat` (Windows)

```cmd
start.bat
```

Скрипт собирает и запускает оба сервиса в отдельных окнах консоли.

### Вручную

Терминал 1 — Rust-сервис:

```bash
cd db
echo "DB_DIR=files" > .env
cargo build
cargo run
```

Терминал 2 — Go-сервис:

```bash
cd api
go build
go run .
```

Приложение доступно по адресу `http://localhost:8090/new`.

## API

### Публичный (Go, порт 8090)

| Метод | Путь     | Описание                              |
|-------|----------|---------------------------------------|
| GET   | `/new`   | HTML-форма новой заметки              |
| POST  | `/new`   | Создать заметку, редирект на `/notes` |
| GET   | `/notes` | Список заметок (HTML)                 |

### Внутренний (Rust, порт 8091)

| Метод | Путь     | Тело                             | Ответ            |
|-------|----------|----------------------------------|------------------|
| POST  | `/save`  | `{"Name": "...", "Text": "..."}` | `200 OK`         |
| GET   | `/notes` | —                                | `[{...}, {...}]` |

## Что было реализовано самостоятельно

- Слой хранения на Rust: HTTP-сервер на `axum`, приём и сериализация JSON,
  запись в файлы по UUID, чтение директории с десериализацией каждого файла.
- HTTP-клиент на Go с единой точкой выполнения запросов (`makeRequest`),
  общим `http.Client` с таймаутом и обработкой не-2xx ответов.
- Разделение логики на слои: хендлеры → клиент к storage → транспорт.
- Обработка ошибок на границе сервисов: различение «наша ошибка» (`500`)
  и «ошибка upstream» (`502`).

## Чему научился в процессе

- Как два сервиса на разных языках договариваются о контракте через JSON.
- Почему `http.NewRequest` без `client.Do` не отправляет запрос — и почему
  «нет ошибок» не значит «всё работает».
- Как отлаживать распределённую систему: изолировать каждый сервис через
  `curl`/`Invoke-RestMethod`, ставить логи на каждой границе.
- Как разделять «наша ошибка» и «ошибка upstream» по статус-кодам.
- Чем `std::fs` отличается от `tokio::fs` и почему блокирующий I/O в async —
  это проблема.
- Как устроен `Post/Redirect/Get` и зачем он нужен.
